Social Commerce Lead Scraper v2

Find Pakistani businesses that sell on Instagram and Facebook but have no website, then export them as ready-to-use lead lists.

Purpose

Many small Pakistani shops take orders by DM or WhatsApp and never build a website. They are natural prospects for web design, ecommerce stores and SaaS tools, but there is no directory of them. v2 builds one from public search results.

Finds

Instagram and Facebook business profiles showing ordering language such as "DM to order", "COD available" or "PKR".

Checks

Whether the business has an independent website, and whether that site is ecommerce or a brochure site.

Delivers

A scored, de-duplicated list split into No Website and Website leads, as CSV, Excel and SQLite.

It does not log in to Instagram or Facebook, bypass bot protection or use private APIs. It reads only what a search engine already shows publicly.

How it works

  1. Discover. For every city × category it builds 18 queries: 8 buying phrases on Instagram and on Facebook, plus 2 plain queries. With --platform instagram or facebook only that site is searched (9 queries). Only the result pages you choose with --pages are fetched. Example query: site:instagram.com "Karachi" "clothing" "DM to order"
  2. Extract. Keeps real profile URLs only (posts, reels and stories are dropped) and pulls the business name, Pakistani mobile number (03xx or +92 3xx), email and WhatsApp number from titles and snippets.
  3. Merge. The same profile found by several queries becomes one lead.
  4. Skip known. Profiles already stored in the SQLite database from earlier runs are dropped, so only new profiles are enriched and existing leads are never overwritten.
  5. Social score. 0–100 for how strongly the business sells through social media.
  6. Local lookup (Brave only). Adds address, phone and website from Brave local places.
  7. Website check. Collects candidate domains (local result, URLs in snippets, a search for the business name and city), loads up to 10, and classes the first live one as ecommerce, business/brochure or unknown. If nothing loads the lead is NO_WEBSITE_LIKELY.
  8. Save and export. New leads are added to the SQLite database. Every output file is then rebuilt from the whole database, sorted by score, so it contains the leads from all your runs.

Setup

Requires Python 3.10 or newer.

python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # Linux / macOS
pip install -r requirements.txt

For Brave only, copy .env.example to .env and set:

BRAVE_SEARCH_API_KEY=your_key_here

Never commit your .env file.

Getting a Brave API key

  1. Register at api-dashboard.search.brave.com/register.
  2. Add a credit card. It is required even for the free credits, and it becomes a live billing card once the free credit is used up.
  3. Choose the Search plan, open API Keys and generate a subscription token.
  4. Paste it into .env. Set a spending cap in the dashboard if one is offered.

Usage

Run the script from the folder you want the results in. Always start with a small test (free DuckDuckGo, no key):

python lead_scraper_v2.py --cities Karachi --categories clothing --pages 1

Instagram only:

python lead_scraper_v2.py --cities Karachi --categories clothing --pages 1 --platform instagram

Continue with deeper result pages later. New leads are added to your existing files:

python lead_scraper_v2.py --cities Karachi --categories clothing --pages 2-3 --platform instagram

With the Brave API (needs a key):

python lead_scraper_v2.py --engine brave --cities Karachi --categories clothing --pages 1

Bigger scan:

python lead_scraper_v2.py --cities Karachi Lahore Islamabad --categories clothing abaya cosmetics --pages 2 --output pakistan.csv

Running again: page ranges and appending

  • Each run adds to the existing data instead of replacing it. Profiles already in the database are skipped; new ones are added.
  • To go deeper, run the same command with a later range, for example --pages 1 first, then --pages 2-3.
  • To accumulate, run from the same folder and keep the same --db and --output. A different folder or file name starts a separate list.
  • Close .xlsx files in Excel before a run, because they are rewritten each time.

Output

Files are written to the folder you run the script from. With --output leads.csv:

FileContents
leads.csvAll leads from all runs
leads_no_website.csvLeads with no detected website: your main prospects
leads_website.csvLeads where a website was found
leads.xlsxThe same two lists as sheets No Website and Website
leads.sqliteMaster store keyed by profile URL; it only grows
JSONOnly with --json-output

The CSV, Excel and JSON files are rebuilt from the whole database after every run, so they always show everything collected so far. The end-of-run summary prints New leads this run and Total leads (all runs).

Columns: business_name, instagram_url, facebook_url, other_social_url, city, category, phone, whatsapp, email, website, website_type, website_status, social_selling_score, website_confidence, local_business, local_phone, local_website, local_address, lead_score, evidence, source_queries, snippets.

The "No Website" list also includes leads that were never checked, for example when you pass --skip-website.

Lead score (0–100)

Starts from the social score. No website +15; website found −30; ecommerce site −70; WhatsApp number +5; local match +5. A strong lead is NO_WEBSITE_LIKELY with a score of 60 or more.

Cost estimate (Brave)

Requests ≈ 18 × number of pages per city/category pair (9 × with --platform instagram or facebook), plus about 2 per new lead (local lookup and website search). Figures assume both platforms and about 40 leads per pair, which is a guess. Leads already in the database cost nothing on later runs.

RunRequestsApprox. cost
1 city, 1 category, --pages 1~100~$0.50
1 city, 5 categories, --pages 2~700~$3.50
8 cities × 9 categories, --pages 2~8,400~$40

Use --skip-local, --platform instagram, scale one city at a time, and set a spending cap. --engine ddg costs nothing.

Limitations

  • NO_WEBSITE_LIKELY is a heuristic, not proof. New, unindexed or private sites can be missed.
  • Only search snippets are read, not full profiles, so many leads have no phone or email.
  • The website check can take up to about 8 s per candidate domain, so big runs are slow.
  • The phone pattern matches Pakistani mobiles only, not landlines.
  • DuckDuckGo may return directory pages (for example "Karachi Clothing Shops") instead of single businesses.
Responsible use. Contact details are public, but using them for outreach is subject to local law, platform terms and anti-spam rules. Review leads before contacting anyone.
